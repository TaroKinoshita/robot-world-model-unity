# P15：action エンコーダの公平な選び方（実験の前に固定する）

- 作成：2026-10-24（**どの候補も回す前に書いた**。あとから変えるときは、変えた日・理由・数値側と画像側の両方に同じ変更をかけたことを末尾に追記する）
- 背景：P14 の小さいモデルで、数値の 2 モデルが学習データすら覚えきれなかった（train の位置誤差 41〜47 mm、画像は 13〜15 mm）。このままだと H3（数値 vs 画像）の差が「表現の差」か「エンコーダの差」か区別できない
- ゴール
  1. 数値モデルが学習データにちゃんとフィットする（画像と同じくらい覚えられる）
  2. 数値側・画像側に、同じ条件・同じ試行回数でエンコーダを選ぶ

---

## 1. 全候補で固定するもの

| 項目 | 値 |
|---|---|
| データ | `Episodes/_p8_20scenes/_cache/wm_128x25.h5`（キャッシュ v3）、分割は `wm_128x25_splits.json`（train 14・val 3・test 3 ペア） |
| エンコーダ以外 | P14 と同じ：初期画像の CNN 5 層、ゴールの MLP、統合 MLP、出力ヘッド、mask デコーダ |
| 損失 | P14 と同じ（位置 smooth L1 ×10、goal・衝突・mask BCE、接触点 smooth L1 ×10） |
| optimizer | AdamW、weight decay 1e-4、batch 16 |
| 学習の長さ | **100 epoch**、cosine で lr を 0 まで下げる（P14 の 30 epoch では数値の loss がまだ下がっていたため。全候補で同じ） |
| lr | **{3e-4, 1e-3} の 2 つ**を全候補で試す |
| seed | 0, 1, 2 |
| 時間の扱い | **数値も画像も同じ 25 時刻**（`raster_steps`）。比べたいのは「数字か絵か」で、時間の細かさではないため。数値の全 step（50 Hz）は診断（§4）でだけ使う |
| test | **選ぶときには一切見ない**。最後に 1 回だけ |

## 2. 候補（数値側・画像側に同じ 4 種類）

どちらも「1 時刻ずつの特徴（トークン）を作る → 時間方向にまとめる」の形にそろえる。違うのは 1 時刻の特徴の作り方だけ（数値 = 小さい MLP、画像 = 1 枚ずつの CNN、重みは全時刻で共通）。

| 名前 | 時間方向のまとめ方 | 数値側 | 画像側 |
|---|---|---|---|
| **E0 base** | P14 のまま | 1D conv 3 層 → 平均 | 25 枚 × 2ch をチャネルに並べた 2D CNN |
| **E1 attn** | 時刻の埋め込み ＋ attention pooling（学習する query 1 つ、4 head） | 1 時刻ずつ MLP | 1 枚ずつ CNN |
| **E2 gru** | 時刻の埋め込み ＋ GRU 2 層 → 最後の状態と平均 | 同上 | 同上 |
| **E3 tf** | 時刻の埋め込み ＋ Transformer 2 層（4 head、CLS トークン） | 同上 | 同上 |

- 出力の次元はすべて 128
- **パラメータ数**：モデル全体で 1.65〜2.25 M（P14 の 4 モデルの平均 1.95 M の ±15%）に入れる。外れたら幅を変えて入れる。全候補の数を記録する

## 3. 判定と選び方

**フィットの基準**（train、Task A・B それぞれ、seed 3 つの平均）：

- 最終位置誤差 ≤ **20 mm**
- goal AUPRC ≥ **0.95**
- 衝突 AUPRC（B）≥ **0.95**

**選び方**（形式ごとに 1 つ。手先と腕全体は同じエンコーダを使う ＝ 範囲の比較をそろえたままにするため）：

1. 候補 × lr のうち、**手先・腕全体の両方**がフィットの基準を満たすものだけ残す
2. 残ったものから、**val の loss（手先・腕全体 × seed 3 つの平均）がいちばん小さい**ものを選ぶ
3. 差が 2% 以内なら、パラメータが少ない方・単純な方（E0 → E1 → E2 → E3 の順）

**どの数値候補も基準を満たさなかったとき**：数値側だけ候補を足すことはしない。足すなら同じものを画像側にも足す（試行回数をそろえる）。それでもダメなら「数値はこの条件では覚えきれない」を結果として書く。

## 4. 診断（選ぶのには使わない。原因を知るため）

| # | 問い | やること |
|---|---|---|
| Q1 | 学習が短かっただけ？ | E0 数値、全 step、100 epoch |
| Q2 | 数値に必要な情報は入っている？ | 手で取り出した特徴（押し始め・押し終わりの手先の位置、押す向き・距離）＋ 箱の初期位置 → 小さいモデル |
| Q3 | 時間の扱いが原因？ | E0 数値、25 時刻 |
| Q4 | 数値と画面の位置の対応づけが原因？ | E0 数値に箱の初期位置・向きを直接渡す（**本番には使わない**） |

## 5. そのあと

- 全部の結果（ダメだった候補も）を `Docs/encoder_fix/` に残す

## 追記

### 追記 1（2026-10-24 01:20 頃、本番の比較を始める前）

- 変更：フィットの基準の「衝突 AUPRC ≥ 0.95」は、**matched pair の候補を除いた Task B の episode** で計算する（全部の episode での値も記録する）
- 理由：matched pair の 2 本は、手先の入力が同じになるように作ってある（P14）。片方だけ衝突するので、手先モデルは学習データでも原理的に両方は当てられない。全部の episode で基準を当てると、手先モデルはどんなエンコーダでも満たせず、「両方の範囲が基準を満たす」候補が 1 つも残らなくなる
- 公平さ：数値側・画像側の 4 モデルすべてに同じ定義を使う。気づいたのは診断の run（eef_num の衝突 AUPRC が 0.94〜0.95 で止まった）を見たとき。本番の比較の結果はまだ 1 つも見ていない

### 追記 2（2026-10-24 19:15、結果が出たあと。ルールの変更ではなく記録）

- 診断のときに回した 4 run（`{eef,full}_{num,img}__base__raster__lr0.001__s0`）は、追記 1 の前に回したので「matched pair 以外の衝突 AUPRC」が記録されていない。本番の比較では同じ設定の run として再利用した（同じ設定・同じ seed なので回し直していない）
- この 4 run は、選ぶときに「全部の episode の衝突 AUPRC」で判定されている（追記 1 より厳しい）。影響するのは base・lr 1e-3 の 2 候補だけで、どちらも基準を満たし、val loss でも選ばれなかったので、結論は変わらない（`Learning/wm_encoder_select.py` で確認）

### 追記 3（2026-10-30、指導教員の指示による変更。§3 の選び方から外れる）

- 変更：本番（`Episodes/_main_v1` 以降）の action エンコーダは、数値・画像とも **E0 base（CNN）** に統一する
  - 数値：1D conv 3 層 → 長さのマスク付き平均（`wm_smoke_train.NumEnc`）、lr **1e-3**
  - 画像：25 枚 × 2ch をチャネルに並べた 2D CNN 5 層（`wm_smoke_train.ImgEnc`）、lr **3e-4**
  - §3 で数値側に選ばれた E2 gru は使わない
- 理由：Week 9 の MTG（2026-10-27 頃）で指導教員から、action エンコーダは全部 CNN で学習させること、ネットワークの決め方は先行研究に寄せることを指示された。根拠にする文献は `cnn_design.md`
- 数値の lr を 1e-3 にした理由：数値の E0 で §3 のフィット基準を満たしたのは lr 1e-3 だけ（lr 3e-4 は手先 goal AUPRC 0.793・腕全体 0.926 で基準 0.95 未満）。画像の E0 は §3 で選ばれた lr 3e-4 のまま
- 記録しておくこと（数値に不利な方向かもしれない）：§3 の val loss は、数値 E0（lr 1e-3）が手先 4.134・腕全体 3.650、選ばれていた E2 gru（lr 3e-4）の平均は 3.092。val は 3 ペアだけなので、差の大きさは §5 の再確認で見る
- 公平さ：数値側・画像側とも同じ E0 を使い、パラメータ数は 1.75〜1.97 M（§2 の範囲 1.65〜2.25 M の中）。手先と腕全体は同じエンコーダのまま
- §5 の再確認（量産データ 50〜100 ペア）は、この E0 の 4 モデルで行う

### 追記 4（2026-10-31 00:20 頃、F の run を回す前に書いた）

- 背景：量産データ（`results_main_v1`・`results_es_v1`）で、画像モデルは val loss が 3〜4 epoch で最小になり、その後は丸暗記に進む。early stopping でも val goal AUPRC は 0.53〜0.56（種類だけの基準 0.77 より下）。数値モデルは 19〜30 epoch で最小、goal 0.91〜0.96
- 考えた原因：E0 の画像は 25 時刻 × 2ch を最初の層でまとめて混ぜる（入力 約 82 万個 / action、数値は 175〜1,725 個）。学習 action 約 3,500 に対して入力が大きく、丸暗記しやすい（DrQ, Kostrikov et al. 2020 と同じ現象）。動画では空間と時間を分けて畳み込むのが標準（(2+1)D, Tran et al. 2018）
- 足す候補 **F（conv）**：1 時刻ずつの特徴（トークン）を作り、**数値の E0 と同じ形の 1D CNN 3 層**で時間方向にまとめ、長さのマスク付き平均。全部 CNN のまま
  - 画像：1 枚ずつ（mask + depth の 2ch）同じ 2D CNN（§2 の ImgTokens、重みは全時刻で共通）
  - 数値：1 時刻ずつ小さい MLP（§2 の NumTokens）。**§3 の「画像側に足すなら数値側にも同じものを足す」に従い、両方に足す**
  - 時刻の埋め込みは使わない（1D CNN が順番を扱うため。数値の E0 と同じ）
- 学習の設定：lr は E0 と同じ（数値 1e-3、画像 3e-4）、最大 40 epoch、cosine、**毎 epoch val を測り val loss 最小の epoch の重みを使う（early stopping）**、8 epoch 続けて改善しなければ打ち切り。seed 0 だけで始める
- 比べる相手：`results_es_v1` の E0（同じ seed 0、early stopping、打ち切りなし）
- 見る指標（val。test は使わない）：goal AUPRC・衝突 AUPRC（全部・pair 以外）・位置誤差・best epoch。パラメータ数が §2 の範囲（1.65〜2.25 M）に入っているかも記録する
- 判定（この結果で本番のエンコーダを決めるのではなく、指導教員と相談する材料にする）：
  1. 画像の F が、画像の E0（early stopping）より goal AUPRC で 0.05 以上良ければ「時間と空間を分けるのが効く」とみなす
  2. 数値の F が数値の E0 より悪くなっていないかも同じ基準で見る
  3. seed 0 で差が見えたら、seed 1・2 を足して確かめる
