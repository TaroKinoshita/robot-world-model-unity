## 3. 分かったこと

1. **位置は 4 モデルとも、種類だけの基準（71 mm）より大幅に良い**（7.5〜13.7 mm）
2. **画像モデルの goal AUPRC が低い（0.47 前後）**。種類だけの基準（0.77）より下。データを増やしてもほぼ伸びない（0.42 → 0.47）
3. **画像モデルは学習データを覚えすぎている**：train の位置 0.4 mm に対して val 13 mm。val loss もデータを増やして下がらない
4. **衝突 AUPRC は全モデル 0.70〜0.80** で、種類＋枝の基準（0.735）をはっきり超えるのは腕全体・数値（0.80）だけ
5. **数値モデルは、データを増やすとまだ伸びている**（手先の位置 11.6 → 9.3 → 7.5 mm、goal 0.76 → 0.87 → 0.94）。頭打ちではない

## 4. 画像モデルが goal で弱い理由の仮説（未検証）

- 画像の action エンコーダと初期画像のエンコーダは **別々の CNN で、最後に平均プーリング**している。平均プーリングで「画面のどこにあるか」がほぼ消えるので、カメラにそろえた画像の強み（初期画像の箱や、ゴールとの位置関係）が使えていない可能性がある
- ゴールは数値（world の x, z と画面の u, v）で渡している。数値の action は同じ world 座標なので、ゴールとの比較がしやすい。画像の action は、この比較を平均プーリングの後の特徴でしなければならない
- このままだと、H3（数値 vs 画像）の差が「表現の差」なのか「画像エンコーダの作りの差」なのか区別できない（protocol の最初の問題意識と同じ）
