# H5 の詳しい分析（探索的、事前に決めた指標ではない）— seed 5 つ版（protocol 追記 7）

- 対象：`results_main_v1v2_ckpt` の腕全体モデル（full_num、full_img）× seed 5 つ（0〜4）。val（77 シーンペア）と H5 評価専用セット `_h5_v1`（126 シーンペア）
- seed 3・4 は追記 7 で追加（RunPod 4090、seed 0〜2 と同じ環境）。seed 3 つ版の結論は git 履歴（3d457c7）に残っている

- CI は 95%、シーンペア単位の bootstrap 2000 回。**seed のばらつきは CI に入っていない**（seed ごとの値を別に示す）
- 組 = matched pair の中で片方だけ円柱に当たる組。「両方同じ」= 2 本とも当たる／2 本とも当たらない組
- **AUROC**：組ごとに c_up − c_down（wrist_up 側の衝突確率 − wrist_down 側の衝突確率）を出し、「up 側が当たった組」と「down 側が当たった組」をどれだけ分けられるか。全体を一定量ずらす偏りの影響を受けない。手首の向きだけの基準は AUROC = 0.5

## 分かったこと

1. **seed を増やしても結論は変わらない。** 新しい seed 3・4 は、数値が 0.781・0.778、画像が 0.597・0.622。どちらも seed 0〜2 の範囲の中に入り、平均はほぼ同じ（数値 0.725 → 0.747、画像 0.598 → 0.603）
2. **腕全体・数値は 5 seed すべてで balanced > 0.5、AUROC > 0.5**（balanced 0.601〜0.893、AUROC 0.658〜0.956）。ただし seed によるばらつきは大きいまま。seed 0 の 0.893 が特に高く、残りの 4 つは 0.60〜0.78
3. **腕全体・画像も 5 seed すべてで 0.5 は超えるが、差は小さい**（balanced 0.585〜0.622）。wrist_down 側は 5 seed とも 0.5 未満（0.262〜0.410）。一方で AUROC は 0.673〜0.772 で、順番としては組の違いの情報を持っている
4. **wrist_down 側の失敗は「wrist_up の方が当たりやすい」という一律の偏りから来ている。** 両方同じ組でも、全モデル・全 seed で c_up − c_down がプラス（+0.16〜+0.41）。数値モデルでは偏りが大きい seed ほど wrist_down 側が低い（+0.159 → 0.852、+0.414 → 0.344）。train では当たる側の約 73% が wrist_up なので、学習データの割合を覚えたもの
5. **val より H5 セットの方が低い**（数値 balanced 0.836 → 0.747、AUROC 0.947 → 0.833）。H5 セットは wrist_down 側が当たる組を意図的に増やしているので（`forceOverlapBranch=alternate`）、学習データと割合が違う
6. 参考：5 seed の確率を平均して 1 つのモデルにすると、H5 セットで数値 balanced 0.786・AUROC 0.886、画像 0.585・0.733

## 論文・報告での書き方の案

- H5 の主張は「腕全体モデルは、手首の向きの偏りだけでは説明できない、組ごとの違いを捉えている」。数値モデルについては 5 seed 全部でそう言える。画像モデルは「0.5 は超えるが差は小さく、wrist_down 側はほぼ当てられない」
- seed ごとの値と範囲は必ず並べる（CI に seed のばらつきが入っていないため）
- 「wrist_down 側でもちゃんと当てられる」とは言えない（数値でも seed 平均 0.590、最低 0.344）
- **AUROC は結果を見てから考えた指標。** test で使うなら、test を回す前に protocol に追記してコミットする。どの指標で H5 を判定するか（balanced か AUROC か）は Rekha に確認する
