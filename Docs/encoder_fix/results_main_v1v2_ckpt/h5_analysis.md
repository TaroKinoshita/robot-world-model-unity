# H5 の詳しい分析（探索的、事前に決めた指標ではない）

- 対象：`results_main_v1v2_ckpt` の腕全体モデル（full_num、full_img）× seed 3 つ。val（77 シーンペア）と H5 評価専用セット `_h5_v1`（126 シーンペア）
- スクリプト：`Learning/wm_h5_deep.py`（引数なしで実行）。balanced の点推定・CI は `eval_h5_v1.md` と一致することを確認済み
- CI は 95%、シーンペア単位の bootstrap 2000 回。**seed のばらつきは CI に入っていない**（seed は 3 つだけなので別に示す）
- 組 = matched pair の中で片方だけ円柱に当たる組。「両方同じ」= 2 本とも当たる／2 本とも当たらない組
- 新しく見た指標 **AUROC**：組ごとに c_up − c_down（wrist_up 側の衝突確率 − wrist_down 側の衝突確率）を出し、「up 側が当たった組」と「down 側が当たった組」をどれだけ分けられるか。全体を一定量ずらす偏りの影響を受けない。手首の向きだけの基準は差が一定なので AUROC = 0.5

## 分かったこと

1. **腕全体・数値の結果は seed にかなり依存する。** balanced は seed 0 が 0.893、seed 2 が 0.601。平均 0.725 の CI（0.666〜0.780）は seed のばらつきを含んでいないので、そのまま書くと強く見えすぎる。3 つの seed すべてで 0.5 は超えている
2. **wrist_down 側の失敗の大部分は「wrist_up の方が当たりやすい」という一律の偏りから来ている。** 両方同じ組でも、全モデル・全 seed で c_up − c_down がプラス（+0.16〜+0.41）。偏りが大きい seed ほど wrist_down 側の正解率が低い（数値：+0.159 → 0.852、+0.414 → 0.344）。train では当たる側の約 73% が wrist_up なので、この偏りは学習データの割合を覚えたもの
3. **偏りを差し引いて見ると、どちらのモデルも組の中の違いを見分けている。** AUROC は腕全体・数値 0.805 [0.743, 0.861]、腕全体・画像 0.713 [0.624, 0.791]。どちらも CI が 0.5 から離れている。seed ごとでも全部 0.5 より上（最小 0.658）。画像モデルも、確率の大きさは偏っているが、順番では情報を持っている
4. **val より H5 セットの方が低い**（数値の balanced 0.824 → 0.725、AUROC 0.937 → 0.805）。H5 セットは wrist_down 側が当たる組を意図的に増やしたので（`forceOverlapBranch=alternate`）、学習データとは割合が違う
5. 参考：3 seed の確率を平均した 1 つのモデルにすると、数値の balanced 0.773、AUROC 0.878（画像は 0.601、0.726）

## 論文・報告での書き方の案

- H5 の主張は「腕全体モデルは、手首の向きの偏りだけでは説明できない、組ごとの違いを捉えている」。根拠は balanced（事前に考えていた指標）と AUROC（偏りに影響されない指標）の両方。seed ごとの値と、その範囲も必ず並べる
- 「wrist_down 側でもちゃんと当てられる」とは言えない（数値でも seed 平均 0.568、seed によっては 0.344）
- **AUROC は結果を見てから考えた指標。** test で使うなら、test を回す前に protocol に追記してコミットする。どの指標で H5 を判定するか（balanced か AUROC か）は Rekha に確認する
