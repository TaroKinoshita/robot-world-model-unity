# early fusion（fused_ss5）— protocol 追記 11、探索的、test は使っていない

- 何を変えたか：画像モデルの統合のしかただけ。late fusion（初期画像・ゴール・腕の画像を別々に 256 次元にしてからつなぐ）→ early fusion（obs 4ch + ゴール 1ch + 腕の画像 50ch を最初から重ねて、1 つの SS エンコーダで読む）。ほかは本番と同じ（SS、early stopping、全学習ペア、40 epoch、lr 3e-4）
- 学習：seed 0・1 はノート（RTX 4060、torch 2.5.1）、seed 2〜4 は RunPod（RTX PRO 4500、torch 2.8.0、2026-11-12、1 run 約 6.5 分）。終わった run を飛ばす仕組みで続きから回した
- どの run も best epoch が 10〜15 と早い（そのあとは train が下がり val が上がる。過学習が早い）
- 比較の詳細：`compare_late_vs_early.md`（`Learning/wm_fused_compare.py`）、各指標：`eval_val.md`、`eval_h5_v1.md`

## 何が言えるか

- **統合のしかたが原因の一部なのは確か**：early fusion で H5 の balanced が両方のデータで有意に上がり、数値モデルとの差（H5 セット 0.144）の約 6 割が縮んだ。val ではほぼ数値モデルと並ぶ
- **それだけでは足りない**：学習なしの深度ルール（0.895）には遠く、wrist_down 側も 0.5 未満のまま。残りは解像度（1 px ≈ 10.8 mm）やデータ量、学習データの偏り（衝突の 73% が wrist_up）が候補
- 本番の結論（H3 not supported、test の数字）は変えない。これは探索的な追加実験で、考察で「画像が弱かった理由」の根拠として使う
