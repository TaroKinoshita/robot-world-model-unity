# P4-B: シミュレーションのブレの修正と押し方の変更

- 日付：2026-10-04
- ブランチ：`todo6-ur5e`
- テスト出力：`Episodes/_ur5e_test/p4b_*`（git 管理外）

## 1. 結論

- **ブレは消えた**：同じ候補を同じ Play の中で何回回しても、実行した軌跡が全 step で 1 ビットも違わない（`p4b_v12`）
- **A/B も一致**：円柱に触れない候補は、Task A と Task B の最終位置の差が 0.000 mm（`p4b_v15`・`p4b_v17`）
- **押し方を変更**：指を閉じて、手先を 90° 回し、押す方向へ 30° 傾けて、2 本の指先で押す。P4-A までの押し方は、**全候補で箱が横倒し（傾き 90°）になっていた**
- **ラベルの修正**：`target_fell` が高さだけで判定していて、立方体の横倒しを見逃していた → 傾きでも判定する

## 2. ブレの原因

同じ候補（c004）を 1 回の Play の中で続けて回して比べた。

| 試したこと | 最終位置の差（最大） | ズレ始める step |
|---|---|---|
| 元のまま | 9.2 mm | 0 |
| 指の関節も含めて全関節をリセット | 16.6 mm | 219 |
| ＋ Enhanced Determinism（エディタ再起動後） | 変化なし | 219 |
| ＋ 当たり判定を外して付け直す | 変化なし | 219 |
| ＋ ロボットの自己衝突を無視 | 13.6 mm | 288（ターゲットに触れた後） |
| ＋ **候補ごとに新しい物理シーン** | **0（全 step で 1 ビットも同じ）** | — |

- Play をまたぐと、結果は最初から 1 ビットも違わなかった。つまり、PhysX の内部に「前の候補の履歴」が残っていた
- リセットを丁寧にしても、この履歴は消せなかった
- 押し方が不安定（箱が倒れる）なので、1e-8 程度の差が mm〜cm まで育っていた

## 3. 直し方（`EpisodeRecorder.cs`）

| 項目 | 既定値 | 中身 |
|---|---|---|
| `freshPhysicsScenePerCandidate` | on | 候補ごとに `LocalPhysicsMode.Physics3D` のシーンを作り、ロボットと `Objects` を移して実行する。`FixedUpdate` で `PhysicsScene.Simulate` を回す。終わったら元のシーンへ戻す |
| （移す前の処理） | — | ロボットのリンクの Transform を、シーンに置いたときの値（全関節 0）に戻す。物体は落ち着いた位置に戻す。ArticulationBody は移したときの Transform から作り直されるので、こうしないと関節角の 0 がずれる（物理で 0 へ動かすだけだと 1e-6 m ずつズレた） |
| `ignoreRobotSelfCollision` | on | ロボットの当たり判定どうしの衝突を全部無視する。移すたびにかけ直す |
| リセット | — | 指の関節も含めて全関節の位置・速度・力・ドライブの目標を戻す |

- `ProjectSettings/DynamicsManager.asset`：Enhanced Determinism を on にした（単体では効果なし。A/B の一致を確認したのはこの設定のとき）
- 計画失敗のログを `LogError` → `LogWarning` に変えた（Error Pause で Play が止まるため。P5 の項目）

## 4. 押し方の変更

| 項目 | 前 | 後 |
|---|---|---|
| 指 | 全開 | 閉じる（`RobotInitialPose.gripperCloseRad` = 0.6 rad、パッドの中心の間隔 2.7 cm） |
| 指の開閉方向 | 押す方向と同じ（前の指 1 本で押す） | 押す方向と直角（`planner.gripperYawDeg` = 90） |
| 傾き | 真下向き | 指先を押す方向へ 30°（`planner.gripperPitchDeg` = 30） |
| TCP の高さ | ターゲット中心 −1 cm | ターゲット中心（`pushHeightOffset` = 0）。指先は天板の約 1 cm 上 |
| 押し始めの位置 | 指パッドの間隔の半分 ＋ 1.5 cm | 当たり判定の形から（`contactFromGeometry`）。ターゲットの高さ・幅の範囲で一番前に出ている点 ＋ 0.5 cm |

ターゲットの傾き（6 方向、Task A）：

| 押す方向 | P4-A（前の押し方） | 新しい押し方 |
|---|---|---|
| −90° | 横倒し 90° | 鉛直のまま、向き 0.6° |
| 130° | 横倒し | 0.9° |
| 180° | 横倒し | 6.9° |
| −45° | 横倒し | 4.3° |
| −135° | 横倒し | 0.4° |
| 150° | 横倒し | 37.1°（鉛直のまま回る） |

- 先に「閉じる＋90° 回す」だけを試したら、2/6 方向で倒れた。ナックル（指の上の方の部品）が前に出ていて、箱の上の方を押していたため → 30° 傾けて、指先が先に当たるようにした
- 追従誤差（TCP）は最大 0.2〜0.3 mm（前は 6〜7 mm）

### matched pair

- 新しい向きだと wrist-up が transfer の途中で IK に失敗する（手首の関節が ±180° に引っかかる）
- `CandidateSpec.gripperYawFlip`（接近方向まわりに 180° 回す）を追加した。閉じた指は左右対称なので、押し方は同じ
- mp0（c006・c007 を両方 flip）：TCP の差 最大 0.071 mm、前腕の差 平均 22.5 cm、手首 1・2 の差 20.0 cm、ターゲットの最終位置の差 0.067 mm
- **今の円柱の位置（0.20, 0.10）だと、新しい押し方では mp0 のどちらも円柱に当たらない** → 円柱の位置は候補の自動生成で決め直す

## 5. ラベルの修正

- `final_state.json` に `target_tilt_deg` を追加。`target_fell` = 高さが 2 cm 以上下がった **or** 傾きが `fallTiltDeg`（30°）を超えた
- `label_params` に `fall_tilt_deg` を追加
- `validate_episode.py` に追加した検証：`target_tilt_deg` と `target_fell` を最終 pose から再計算して照合、`goal_reached` = 距離 ≤ 半径 かつ 倒れていない
- **P4-A のパイロット（`Episodes/scene_0000`・`scene_0001`）は全候補で横倒しだった**。goal True の 4 件も、実際は「倒れた箱の中心がゴールに入った」もの
